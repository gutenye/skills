# feat2

Spec-driven development.

- Plan is written waterfall: same order as you’d think and write the code
- Each code block has a short description so you can understand it in context
- Plan is short and easy to read — no extra prose
- The PR is the same code you reviewed in the plan, including comments; no surprises
- Full production code in the plan — no “implement X” placeholders
- Review the plan instead of commits
- Bugs lead with Cause and Fix so you can skim the diagnosis first
- Research the code (and linked task/Slack) before trusting the ticket’s investigation
- Work on cross-repo features with multiple worktrees in the same place
